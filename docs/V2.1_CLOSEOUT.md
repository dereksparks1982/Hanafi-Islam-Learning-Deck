### Media architecture: Google Drive replaced by self-hosting

The v1.9/v2.0 Google Drive iframe implementation is no longer the accepted Media architecture.

v2.1 moved Media to a self-hosted path using work extracted from **Nougat Media Plus** while keeping the Hanafi interface independent:

```text
Hanafi GitHub Pages
        |
        | HTTPS
        v
saxondesktop / Nginx
        |
        | 127.0.0.1:8097
        v
Hanafi media bridge
        |
        | 127.0.0.1:8098
        v
Nougat integrated Jellyfin
        |
        v
local Hosted media files
```

Important boundaries:

- movie files remain on the maintainer's own computer;
- GitHub contains the Web App, stable media IDs, manifest examples, server/bridge code, and deployment tooling, not the movie files;
- Jellyfin remains private backend/catalog infrastructure and is not the visible player;
- only manifest-listed items are publicly addressable through the Hanafi bridge;
- unrelated Nougat features such as Games, Live TV, World TV, Search, P2P, AI, radio, security tooling, and its tactical desktop player UI are not imported into Hanafi.

### DK Media becomes the player base

The accepted v2.1 browser player is based on the maintainer's separate **DK Media Player** project.

The browser version does not embed the Python/Tkinter/libVLC desktop application. It carries the useful player behavior into a native Web implementation around one browser video element.

Accepted design:

- **one video player total**;
- library/media selector changes what that player loads;
- no stacked player per movie;
- play/pause;
- rewind 10 seconds;
- forward 30 seconds;
- seek timeline and time display;
- volume control;
- playback-speed control;
- fullscreen;
- keyboard controls;
- remembered volume/speed preferences;
- remembered resume position per media item;
- source link changes with the selected media item;
- external subtitle on/off control when a subtitle is configured for that media item.

The DK Media single-player architecture is now the locked Media-player baseline under the Company Bible.

### Streaming behavior retained from Nougat work

The v2.1 server/bridge layer retains the useful technical work already solved in Nougat:

- stable media IDs instead of exposing filesystem paths to the Web App;
- HTTP byte-range delivery for seekable local media;
- local-file fallback when Jellyfin has not indexed the exact file;
- Jellyfin streaming/transcoding path where useful;
- FFmpeg H.264/AAC MP4 fallback for incompatible source containers;
- CORS limited to the Hanafi GitHub Pages origin;
- HTTPS front end through Nginx;
- health and catalog endpoints;
- SRT-to-WebVTT conversion for browser subtitle playback;
- service/deployment and smoke-test tooling.

### External subtitles

The accepted v2.1 subtitle model is deliberately separate from the video file.

Current manifest format allows **one optional external subtitle file per media item**. If that file is SRT, the bridge converts it to WebVTT when the browser requests it. The DK Media Web player exposes the configured subtitle as an on/off choice.

This allows a clean video master to be reused without creating a second copy merely to burn a subtitle track into the picture.

Multiple named external subtitle tracks per single media item are **not** claimed as a completed v2.1 feature. That can be extended later if explicitly authorized.
