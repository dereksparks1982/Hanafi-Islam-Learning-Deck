# v2.5 Media Metadata Automation Plan

**Status:** CANDIDATE BUILT / AWAITING LIVE RUNTIME VALIDATION  
**Base:** accepted v2.4  
**Branch:** `main`

## Goal

Make public Media onboarding behave like a mature media server instead of requiring a new set of hand edits for every movie.

The target flow is:

```text
Hosted movie folder/file
        |
        v
scan + parse title/year/provider IDs
        |
        v
Jellyfin movie library + metadata/provider matching
        |
        v
normalized Hanafi catalog metadata + poster
        |
        v
cached Web App movie card/page
        |
        v
existing DK Media player
```

## Candidate implementation

The v2.5 candidate now:

- keeps the accepted v2.4 playback bridge byte-for-byte as `server/hanafi-jellyfin-bridge-stable.py` and layers metadata/discovery on top instead of rewriting the working playback implementation;
- scans the configured public Hosted root for recognized movie video files;
- groups a normal movie folder into one automatically discovered public item and assigns a deterministic ID from its relative path;
- parses `Movie Name (Year)` from normal folder naming when provider metadata is not yet available;
- preserves every explicit v2.4 manifest ID and its existing playback path;
- uses the existing Nougat-integrated Jellyfin server as the metadata/provider engine;
- can register the Hosted folder as a Jellyfin **movies** library once, then request normal Jellyfin library refreshes rather than requiring a new manifest/Web App edit for every title;
- enriches explicit and automatically discovered items with Jellyfin title, original title, production year, overview, runtime, provider IDs, and primary-image state when Jellyfin has indexed the file;
- exposes normalized metadata through `/nougat/v1/catalog` without exposing local filesystem paths, Jellyfin credentials, or the Jellyfin management interface;
- adds `/nougat/v1/poster?id=...` with artwork priority of local poster asset, Jellyfin primary image, then cached FFmpeg video-frame fallback;
- lets the Media home page use bridge poster art automatically when an existing film has no hand-wired artwork source;
- creates cards automatically for newly discovered public movies from catalog metadata;
- lets dynamic movie pages receive server metadata without adding a new hardcoded film record;
- preserves the existing artwork manager and manual/locked artwork behavior as the maintainer override path.

## One-time v2.5 runtime update

`media-server/deploy/update-v25-metadata.sh` is the permanent updater for this candidate. It performs the one-time runtime transition needed for the new metadata layer:

1. downloads the v2.5 wrapper and the accepted v2.4 stable playback core from the selected `main` revision;
2. syntax-checks both before installation;
3. installs both files beside each other under `/usr/local/bin`;
4. records the public Hosted root and a writable bridge poster-cache location in the existing Hanafi environment file;
5. checks the private Nougat/Jellyfin server for the Hosted movie-library path and adds it as a **movies** library when it is not already present;
6. requests a Jellyfin library refresh;
7. restarts only the existing `hanafi-jellyfin-bridge.service`;
8. verifies health and prints the live public catalog.

That updater is not a per-movie workflow. Once v2.5 is deployed, adding a correctly named movie under Hosted is supposed to be the movie-onboarding action.

## Provider model being mimicked

The implementation follows the useful architecture already proven by Jellyfin/Plex/Emby rather than copying their UI:

1. scan the library;
2. parse the filename/folder identity;
3. prefer stored provider IDs when available;
4. otherwise let the configured media-server metadata providers match title + year;
5. save/use normalized provider metadata;
6. obtain primary artwork through the metadata provider;
7. cache the result;
8. allow local/manual overrides;
9. refresh without overwriting locked manual choices.

Jellyfin's current movie-library, TMDb metadata-provider, and remote-image-provider flow is the primary implementation reference because Hanafi already runs on top of the Nougat-integrated Jellyfin backend.

## Exclusions

- No second Jellyfin instance.
- No replacement media server.
- No Plex or Emby runtime dependency.
- No redesign of the DK Media player.
- No stacked players.
- No rework of the Private Library.
- No poster-binary collection committed to GitHub.
- No account, telemetry, advertising, or behavioral tracking.
- No automatic overwrite of locked/manual artwork.

## Acceptance boundary

A correctly named movie is added under the Hosted public-media library. After the normal server/library refresh path runs, the movie must become available in the Hanafi Web App with:

- a stable public media ID;
- title and year;
- provider-derived metadata when a verified Jellyfin/provider match exists;
- automatic poster art when the provider has one;
- a local poster when a conventional local poster asset exists;
- a cached video-frame fallback when neither provider nor local poster is available;
- a normal dedicated movie page;
- working playback through the existing Hanafi/DK Media path;
- no hand edit to `web-viewer/media/index.html`, `web-viewer/media/movie.html`, or `media-server/media.tsv.example` for that individual movie.

The eight v2.4 public films must continue to play throughout the build.

## Validation state

The candidate is **not accepted or closed** until that live validation passes and the maintainer accepts it.
