# v2.5 Media Metadata Automation Plan

**Status:** ACTIVE / OWNER-AUTHORIZED  
**Base:** accepted v2.4  
**Branch:** `main`

## Goal

Make public Media onboarding behave like a mature media server instead of requiring a new set of hand edits for every movie.

The target flow is:

```text
Hosted movie folder/file
        |
        v
scan + parse title/year/provider IDs
        |
        v
Jellyfin metadata/provider matching
        |
        v
normalized Hanafi catalog metadata + poster
        |
        v
cached Web App movie card/page
        |
        v
existing DK Media player
```

## Included work

- Detect public movies placed in the configured Hosted library without requiring a new hardcoded Web App movie entry for each title.
- Parse conventional movie identity such as `Movie Name (Year)` and retain support for provider IDs when known.
- Use the existing Nougat-integrated Jellyfin metadata system first, including the providers already configured for that server, instead of attempting unauthenticated TMDb calls directly from the browser.
- Read normalized movie identity from Jellyfin where available: title, original title, production year, overview, runtime, provider IDs, and primary image state.
- Expose safe public metadata through the Hanafi bridge without exposing local filesystem paths, Jellyfin credentials, or the Jellyfin management interface.
- Proxy/cache primary poster artwork through the Hanafi bridge so GitHub Pages can display it without carrying movie-poster binaries in Git.
- Keep local artwork files and explicit maintainer artwork selections as higher-priority overrides when intentionally selected.
- Keep manual artwork locks durable so metadata refresh cannot silently replace a maintainer-approved poster.
- Preserve a truthful fallback when metadata or artwork cannot be matched. Do not invent a movie identity or poster.
- Create future public movie cards and movie pages from catalog metadata automatically.
- Preserve stable explicit IDs for the eight existing v2.4 films while allowing newly discovered movies to receive deterministic public IDs.
- Preserve existing byte-range/transcoding playback and the accepted one-player DK Media Web player.

## Provider model being mimicked

The implementation follows the useful architecture already proven by Jellyfin/Plex/Emby rather than copying their UI:

1. scan the library;
2. parse the filename/folder identity;
3. prefer stored provider IDs when available;
4. otherwise match title + year through configured metadata providers;
5. save provider IDs and normalized metadata;
6. obtain primary/alternate artwork through the metadata provider;
7. cache the result;
8. allow local/manual overrides;
9. refresh without overwriting locked manual choices.

Jellyfin's current TMDb movie provider is the primary implementation reference because the Hanafi server already runs on top of Nougat-integrated Jellyfin.

## Exclusions

- No second Jellyfin instance.
- No replacement media server.
- No Plex or Emby runtime dependency.
- No redesign of the DK Media player.
- No stacked players.
- No rework of the Private Library.
- No poster-binary collection committed to GitHub.
- No account, telemetry, advertising, or behavioral tracking.
- No automatic overwrite of locked/manual artwork.

## Acceptance boundary

A correctly named movie is added under the Hosted public-media library. After the existing server/library refresh path runs, the movie must become available in the Hanafi Web App with:

- a stable public media ID;
- title and year;
- provider-derived metadata when a verified match exists;
- automatic poster art when the provider has one;
- a normal dedicated movie page;
- working playback through the existing Hanafi/DK Media path;
- no hand edit to `web-viewer/media/index.html`, `web-viewer/media/movie.html`, or `media-server/media.tsv.example` for that individual movie.

The eight v2.4 public films must continue to play throughout the build.
