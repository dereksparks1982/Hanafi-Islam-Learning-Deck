# Hanafi Learning Deck v2.4 Closeout

**Status:** CLOSED AND ACCEPTED  
**Closeout date:** 2026-09-29  
**Branch:** `main`

## Release boundary

v2.4 closes the work completed after the accepted v2.3 checkpoint. It records the current Web App, card-library, private-library, and public Media state before the next Media metadata build begins.

## Completed in v2.4

- Expanded the published card resources to **222 total**: the established 209-card library plus **13 glossary/index cards** I-1 through I-13.
- Kept current development on the single `main` branch.
- Stabilized the current Web App launch/cache behavior and the separate Deck page without restoring rejected Home layouts.
- Retained the approved Hanafi Learning Deck icon, Home background, devotional opening, prayer tools, Qur'an Reader, Explore, Live, Links, Charity, About, and Legal surfaces.
- Retained the locked Advanced Learner Library and its current five-slot private-library entrance treatment.
- Expanded public Media from four films to **eight** explicit film pages while preserving the accepted single DK Media Web player.
- Added **Aao Hajj Karein (2012)**, **Joseph in the Land of Egypt (1914)**, **Pakistan (1950)**, and **The Soviets and Islam (1972)**.
- Repaired **Al-Risalah (1976)** after its local Hosted folder was renamed by updating its media path rather than treating the film as unsupported.
- Restored the stable Hanafi media bridge after a rejected bridge regression and preserved the existing Nginx -> Hanafi bridge -> Nougat/Jellyfin -> local-media architecture.
- Confirmed with the maintainer that **all eight public movies play** at closeout.
- Preserved the existing artwork manager, IndexedDB poster cache, local artwork-folder support, manual artwork URL/file controls, and locked manual selections.

## Known v2.4 limitation

The four newly added films play correctly but do not yet receive box art automatically. Their records currently have stable artwork cache keys but no automatically resolved provider artwork. The existing browser artwork manager contains manual/provider-search pieces, but automatic metadata resolution is not yet wired into new-movie onboarding.

This is intentionally carried into **v2.5**, rather than patched by manually hardcoding four more poster URLs.

## v2.5 handoff

The maintainer authorized **v2.5** as the next build. Its purpose is Plex/Emby/Jellyfin-style automatic movie onboarding: detect a correctly named Hosted movie, identify it from title/year/provider IDs, use the existing Jellyfin metadata/provider system, expose normalized metadata and poster art through the Hanafi bridge, cache results, and create the Web App card/page automatically without hand-editing `index.html`, `movie.html`, or the public manifest for each future movie.

Existing working playback, the eight current films, the one-player DK Media architecture, private-library behavior, and explicit manual artwork locks are preservation requirements.

No version after v2.5 is assigned by this closeout.
